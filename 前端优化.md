## Shared axioms (all four rulesets agree — apply always)

- **No design system = no UI work.** `DESIGN.md` exists before components do; every color, font size, and spacing value traces back to a token in it.
- **Concrete reference = contract.** When a screenshot, generated mockup, overview, or annotated reference exists, the implementation must match its pixels, copy, component structure, and responsive intent unless the user explicitly accepts a deviation.
- **Never weaken UX OR flatten the surface to buy points.** No dropping animations, hiding content, simplifying interactions, or replacing rendered/lit material with flat fills and flat geometric primitives for a Lighthouse score or a deadline. Hit 100 AND keep the surface dimensional — both, or neither.
- **No emojis as icons.** SVG icon sets only (Lucide, Heroicons, Radix, Phosphor).
- **GPU-composited animation only** — `transform`, `opacity`, `filter`; never animate layout properties.
- **Slop animation is forbidden — motion serves meaning.** Every animation or hover must map to a real interaction, state change, or affordance. A hover that changes nothing, motion on a non-interactive element, or a decorative micro-animation with no informational purpose is slop — do not add it.
- **Done is the `/visual-qa` dual-oracle gate, not your own glance.** A frontend design task is verified through `/visual-qa` (real browser at 375 / 768 / 1280px, every page, with interaction states and motion driven and inspected) until the dual-oracle completion gate passes on fresh evidence.

## 11. Likely Responsive Concerns

1. **Sidebar at ≤1280px.** 336px fixed + two cards will crush the right panel below usable width. The collapse icon in the user block suggests a mini-rail exists — but it's buried at the bottom instead of at the top of the sidebar where users expect it.
2. **Two-column card grid at ≤1024px.** The 68/32 split must stack. Stacking naively puts 课程文档 *below* a very long accordion — the upload flow becomes unreachable without scrolling past 30+ rows. It should either move above the accordion on mobile or become a drawer/modal.
3. **Row overflow on narrow screens.** `AI 主要流派（符号主义/连接主义/行为主义）` + chip + `生成视频` needs ~700px. Under ~560px the title will wrap into 2–3 lines while the chip/action stay vertically centered, or the action will be pushed off-canvas. Needs a defined wrap rule (title on line 1, chip+action right-aligned on line 2) or an overflow menu.
4. **Header collision.** `返回课程列表` (5 chars + icon, ~170px) + `人工智能导论` at 27px will not fit on a 375px viewport; the back button should degrade to an icon-only chevron.
5. **FAB overlaps content.** At bottom-right over a scrolling list, it will cover the trailing row's `生成视频` action on narrow screens — no bottom safe-area padding is visible on the list.
6. **Chip + link tap targets.** `生成视频` is text ~72px wide but its clickable height is likely only the ~20px text box; the icon is ~22px. Both are under the 44px touch minimum.
7. **Empty-state illustration** (~90×70 line art) is fine, but the centered layout will look stranded in a full-width stacked card.
8. **Deep indentation** (chevron + icon + text ≈ 130px of leading chrome before content) is unaffordable on mobile; the hierarchy icon should be the first drop.

- 资源中心四列卡片太空
- 课程管理左侧信息密集，右侧文档上传区域过于空旷
- 学习画像两列卡片高度不一致，破坏网格节奏

建议：

- 学习路径采用约 40% / 60% 的主从布局
- 课程管理右侧增加文档列表、上传状态和文件信息
- 资源中心改为 3 列或响应式网格
- 学习画像卡片采用等高或内容折叠策略

### 3. 页面缺少全局顶部工具栏

当前大量功能都被放在侧边栏或页面内部，缺少统一的顶部上下文。

建议增加轻量顶部栏，包含：

- 面包屑
- 页面标题或当前课程
- 全局搜索
- 通知
- 用户菜单
- 侧边栏折叠按钮

对于课程详情页尤其需要：

> 课程管理 / 人工智能导论 / 章节与知识点

## 五、色彩和字体问题

### 1. 蓝色使用范围过广

蓝色同时用于：

- 主按钮
- 活跃导航
- 链接
- 标签
- 图标
- FAB
- 用户头像
- 生成操作

结果是蓝色无法区分：

- 主要操作
- 当前选中
- 普通链接
- AI 功能
- 状态信息

建议定义颜色语义：

- 主色：主要操作
- 靛蓝：导航选中
- 紫色：AI 能力
- 绿色：完成 / 成功
- 橙色：提醒 / 待处理
- 红色：错误 / 阻塞
- 灰色：禁用 / 次要信息

---

### 2. 一些文字对比度偏低

需要重点检查：

- 侧边栏分组标题
- 卡片辅助文字
- 空状态说明
- 输入框 placeholder
- “待开始”标签
- 资源卡片中的查看提示
- 学习画像字段标签

部分浅灰文字在白色背景上可读性不足，尤其是中文小字号文本。

建议：

- 正文颜色不低于深灰级别
- 辅助文字保持可读，不要仅依靠低对比度表达次要性
- 重要状态不能只依靠颜色区分

---

### 3. 字体层级和中英文混排不够统一

存在：

- CJK 与英文间距不统一
- `easy / medium` 混入中文界面
- 英文模型名直接暴露
- 过长中文文本出现不自然断行
- 用户气泡中“机器学习”被拆开
- 长英文字符串可能造成溢出

建议：

- 统一使用中文标签：简单 / 中等 / 困难
- 统一中英文间距
- 对长英文使用截断或换行策略
- 中文正文行高控制在约 1.6～1.8
- 对标题限制 1～2 行并提供展开

## 总结

当前页面最大的问题不是单个组件不好看，而是：

1. 信息层级不够明确  
2. 入口重复，操作语义不清  
3. 空状态和 AI 状态不完整  
4. 卡片留白过多，内容密度不均
